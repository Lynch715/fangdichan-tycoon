# 房地产大亨

以现金流为核心的房地产开发模拟经营游戏：拍地、融资、施工、预售、清盘，用杠杆扩张，在周期和监管中活下来。背景映射重庆，等距视角，桌面和手机浏览器都能玩。

开源项目，用于内部交流。

施工单 A–D 已完成本地实现与验收；最新存档v16，374项测试通过。完整证据和未覆盖范围见[最终验收索引](tests/acceptance/FINAL-REPORT.md)。当前尚未发布。

## 运行

需要 Node.js 22.18 或更新版本（脚本使用原生 TypeScript 类型擦除；CI 使用 Node.js 22 最新补丁版）。

```bash
npm install
npm run dev
```

打开终端里显示的地址。手机和电脑在同一个局域网时，用 Network 那一行的地址在手机上访问。

## 怎么玩

- 回合制：一回合 = 一个游戏月。每回合开始时弹出“回合简报”：① 回合、月份、季节、现金、净资产；② 上回合各项目签约销售与现金净流入（另列融资利息、员工薪酬）；③ 金融市场行情（周期、情绪、评级、红线档位、各片区均价与月涨跌、各融资渠道本回合新增利率）；④ 本回合生效的季节/政策事件和上回合动态；⑤ 待处理事项。
- 看完简报后自由操作（拍地、开工、融资、调价、招聘派驻员工……），点顶栏“结束回合”推进一个月并结算。月末抽取下一回合的季节/政策事件。点顶栏回合号可随时重看简报；财务页底部可关闭自动弹出。
- 新地块挂牌、拿地后待选总包、到期款超过现金、监管政策变化等，不再打断游戏，汇总为简报里的“待处理”。
- **季节与季节/政策事件**：3–5 月春、6–8 月夏、9–11 月秋、12–2 月冬。每季有基础去化/施工系数，每月至多抽一个事件，如春季房交会、两会定调（新增融资利率 −0.5%）、主汛期暴雨、高温限电、金九银十、国庆看房潮、季末信贷紧张（+1%）、年末冲业绩、春节返乡、年底资金面收紧。事件作用于全市场（同行同样受影响），一年平均下来对去化、工期基本中性。数值在 `data/config.json` 的 `seasons`。
- **员工体系**：财务页“员工与人才市场”。每 3 个回合刷新 4 位候选人，各有工程/营销/财务/公关四项能力，主能力越高月薪越贵（签约时付 2 个月签约费，解雇付 3 个月补偿）。岗位：项目经理（工程，加快施工、降低事故、每月提升质量）、销售经理（营销，提高该项目去化）、财务总监（财务，压降新增融资利率）、公关总监（公关，每月降低监管关注度）。效果按能力等比例生效，在岗员工每月有机会成长；项目退出经营后员工自动回总部待命，待命也照常领薪。数值在 `data/config.json` 的 `staff`。
- 右侧“本季土地拍卖”里出价，开拍日揭晓结果。出价要先交 20% 保证金；拿地后先付 50%，余款 6 个月内付清；在项目卡选择总包开工，下一月末开始支付工程款。
- 左侧“融资”里借信托（可用于拿地，利息高）或开发贷（只能用于在建项目，利息低）。
- 工程进度到 25% 后自动开盘预售。售房款先进监管账户，按工程进度释放。
- 第 5 年起“三道红线”生效，踩线越多，有息负债的增速上限越低。
- 账上现金为负即进入违约，6 个月内补不上就破产。

## v0.2 新增玩法

- **商票**：项目内开启后，用票据支付本公司承担工程款的 50%，不直接增加现金。12 个月后兑付；票据计入总负债及到期预警，不能展期。
- **明股实债**：财务面板可融入，额度为净资产的 50%，初始年化 15%、期限 24 个月，叠加评级利差。按实质计入有息负债；抽查披露会罚款和冻结新增融资。
- **合作开发**：尚未预售、没有项目融资的在建项目可出让 30% 权益。合作方按已投入土地款与工程款的 30% 出资，此后按权益分摊成本和回款；无法重复引入。
- **违规与抽查**：独资项目可以挪用锁定监管款的 25%，监管关注度上升。每月按关注度抽查，追缴尚未合法释放的挪用款、罚款，并冻结新增融资 3 个月。
- **限价备案**：调控、下行阶段须有备案才能销售；申请时按市场价的 95% 备案，30 个游戏日审批。限价期按备案价与项目售价孰低成交，可申请更新。
- **随机事件**：月度可能发生建材涨价、事故停工和配套利好。加速施工的事故概率更高；新闻和回合简报保留事件结果。
- **自救**：有息债务到期前 6 个月内可申请一次展期，延期 6 个月，费用 2%，年利率加 2 个百分点，需现金支付。商票不能展期。项目转让按账面净资产折价，并先结清项目融资；若承接义务大于资产，转让需要补付，界面会明确显示。挪用监管款未处理时不能转让。
- **远郊地图**：第 3 年开放璧山和江津；土地更便宜、容积率更低。两张地图独立占地，切换后拍卖列表跟随地图，项目列表统一显示。

## 存档与离线

财务面板显示存档与离线缓存状态，并可导入、导出 JSON。IndexedDB 为主存档，localStorage 保留同步备份；原 v0.1 存档读取时先按原规则回放，新增玩法从续玩日期开始。导入失败保留当前进度，无法读取的原档不自动覆盖。

运行 `npm run build` 后，用 `npm run preview` 或静态服务器访问。首次联网等待“离线缓存已就绪”后可离线启动。支持 PWA 的浏览器可以安装到主屏幕；本次未测试系统安装。更新提示出现时，关闭该游戏全部标签页再打开；已有经营日志随存档保留。`npm run dev` 不启用离线缓存。

## 发布到 GitHub Pages

本节对应 C1/C2 发布准备。当前尚未初始化 Git、推送或上线，远程工作流尚待首次运行核验。

1. **由你在本机初始化仓库**，将本目录 `game/` 作为仓库根目录：根下应直接有 `package.json`、`src/`、`public/` 和 `.github/workflows/deploy.yml`。不要把 `game/` 再嵌入仓库的一层子目录，否则 GitHub 找不到工作流。若自行采用上一级为仓库根，需要同步移动工作流并调整工作目录、锁文件缓存路径及上传产物路径。
2. 本地先执行下方验证命令。把源码、`package-lock.json`、`public/` 图集和图标、测试、脚本及工作流纳入版本管理；`node_modules/` 和 `dist/` 已被忽略。构建使用现成的 `public/art/`，不会重新生成图片。
3. 在 GitHub 建立远程仓库并连接本机仓库，在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。仓库须支持 Pages，并允许使用官方 Actions；发布环境为 `github-pages`。
4. 将准备好的提交推送到 **main**。工作流自动依次执行 `npm ci`、`npm test`、`npm run build`，仅将 `dist/` 上传为站点产物，测试或构建失败不会发布。也可在 Actions 选择 **Deploy game to GitHub Pages → Run workflow**；只有 main 可以部署。
5. 在 Actions 查看 build 和 deploy 均成功后，打开部署输出的 Pages 地址。普通项目地址形如 `https://你的账号.github.io/仓库名/`，保留末尾斜杠。项目目前使用相对资源路径，manifest、图集和离线脚本均随该目录部署。
6. 首次发布后核对地图贴图、开局、导入/导出和离线状态；手机首次安装后再检查一次存档。后续更新推送 main 即重新构建发布。以 Actions 成功和实际站点验收为准，本地构建成功不等于已经上线。

```bash
npm ci
npm test
npm run build
npm run preview -- --host 127.0.0.1
```

本地预览使用终端显示的 HTTP 地址，不直接打开 `dist/index.html` 文件。发布流程参考 [GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) 与 [Vite 静态部署说明](https://vite.dev/guide/static-deploy)。

## 添加到手机主屏幕（PWA）

使用已发布的 **HTTPS** 游戏地址，先联网打开并等待页面提示“离线缓存已就绪”。局域网普通 HTTP 开发地址主要用于界面检查，不能替代 HTTPS 下的安装与离线验收；`npm run dev` 本身也不启用离线缓存。

### iPhone（Safari）

1. 在 Safari 打开游戏地址；若从聊天应用进入，先选择在 Safari 中打开。
2. 点共享按钮；部分布局需要先打开页面菜单再点“共享”。
3. 选择“添加到主屏幕”；没有此选项时，到共享列表底部的“编辑操作”中添加它。
4. 若出现“作为网页 App 打开”，保持开启，确认名称后点“添加”。
5. 从主屏幕图标重新进入游戏，联网等待缓存就绪后，再断网重新打开验证离线启动。

菜单会随系统版本和 Safari 布局变化，见 [Apple 官方安装说明](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)。

### Android（Chrome）

1. 在 Chrome 打开游戏的 HTTPS 地址。
2. 点地址栏旁的三点菜单，选择“安装并创建快捷方式 → 安装”。部分版本显示“添加到主屏幕 → 安装”或“安装应用”。
3. 按提示确认，从主屏幕或应用列表中的“地产大亨”图标打开。
4. 等待离线缓存就绪，再断网重开验证；只创建网页快捷方式不代表离线资源已下载。

菜单以当前 Chrome 显示为准，见 [Google 官方 Web 应用安装说明](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=zh-Hans)。

### 存档和更新

存档保存在当前设备的浏览器或独立网页 App 中，不是云同步。安装前先导出 JSON；从图标启动后若没有原进度，用“导入存档”读取该文件。更换设备、浏览器、域名或清除网站数据前也应导出。

看到离线更新提示后，先保存并关闭本游戏全部标签页和独立窗口，再联网重开。无需为更新清除网站数据。正式安装、首次缓存、断网启动与存档重载应在实际手机上验证；本项目目前记录的是应用内浏览器与模拟手机视口验收，尚未完成 iPhone/Android 系统安装实机测试。

## 拍地测算（B1）

在拍卖卡片中输入报价，即时显示标为“估算”的预期利润率、资金峰值和自有资金回正月数；空值或低于起拍价时提示输入有效报价。未提交报价会在本次页面中保留，只有点击“出价/改价”才形成指令和保证金支出，刷新页面后以已提交报价为准。

口径为按输入报价成交、独资标准总包正常施工、不新增借款，品牌保持当前值、营销按默认3%固定；拿地后立即选定开工，下一月末支付首笔工程款。使用当前房价、销售剩余面积的月度去化率和监管释放规则，并假设它们保持不变；限价时及时备案，尾货按现行清盘折价全部售出。资金峰值包含土地分期、工程款及监管回款释放前的营销/税费占用，保证金抵首付不重复计成本；利润不含融资利息、事故或其他项目的资金占用。中标当月计第1个月，自有资金回正是月末累计收支非负且此后不再转负；最终亏损时显示“无法回正”。这是一项固定情景估算，实际周期、成交价和经营决策会改变结果。

### 停工与政府接管

当月工程款的现金部分不足，项目停止施工，不扣该笔工程款、不增加进度，也不为未施工工程签发商票。商票和合作按各自比例计算现金部分。连续6个月结算未能实际复工则政府接管，监管款、剩余货值与交付义务移交，地图显示烂尾；原公司借款、商票和未付地价仍需偿还。第6次结算前补资，可在月末支付工程款后复工并清零停工计数。项目卡显示的是上次月末工程款缺口，之后的建材波动、其他支出可能改变实际所需资金。

事故停工单独计时，不直接启动资金停工计数；已因资金停工且未实际复工时连续计时。土地款、税费、利息、到期债务和事故支出仍可能使现金为负，停工不免除这些义务。停工但已有预售资格的项目仍可销售自救；接管后停止经营。

### 总包与质量（B3）

拿地后列入回合“待处理”，先显示围挡；在项目卡选定低价、标准或品牌总包后开工，选择不可更换。未开工时不付工程款、不增长进度，土地尾款仍须按期支付。界面显示三档建安预算、正常工期、月事故率和初始质量。

低价总包成本为标准的90%、工期115%、事故风险150%、质量55分；标准为100%/100%/100%、75分；品牌为112%/90%/60%、90分。加速施工仍有原有成本和事故倍率，事故每次降低质量10分。交付质量低于60分时只触发一次业主维权，公司品牌扣10分、监管关注加15，品牌初始50分且最低0，关注度最高100。项目与财务面板显示分数。品牌与营销对去化的联动已在B4接入。

旧档历史保持原成本、工期和随机序列，原项目补为标准总包、质量75分，从续玩后才计算新的质量事故和维权。完整参数、旧档冻结验证与浏览器证据见[tests/acceptance/B3-REPORT.md](tests/acceptance/B3-REPORT.md)。

### 品牌与营销（B4）

公司品牌0–100分，初始50；达标交付+2，低质量维权−10。品牌会影响所有项目的月度去化。每个在售项目可在项目卡设置营销投入比例0–12%，默认3%；费用只按当月实际销售回款计提，按合作权益分摊，不是固定预付预算。营销较高会提高去化，也会提高销售费用；设为0可以停止营销费用，但仍受价格、市场和品牌影响，去化不会保证为零。

在品牌50、营销3%时去化基准不变；品牌从0到100对应0.7–1.3倍，营销0–12%对应0.88–1.36倍，仍受最高月去化限制。面板显示当前比例与预计去化，预测未计配套利好。达标交付和维权只在交付时结算一次。完整费用核对、旧档逐字段保护和真实设置重载证据见[tests/acceptance/B4-REPORT.md](tests/acceptance/B4-REPORT.md)。

### 项目结算与经营报表（B5）

财务面板点击“经营报表与复盘”查看月报、年报、项目结算和经营复盘。清盘时自动暂停并弹出结算，同月多个项目分列展示；破产时自动打开复盘。

三张表分别展示期末资产负债、本期收入成本费用、可用现金流。预售回款先作为合同负债，交付后确认收入；借款不计利润，监管资金另列资产。年报只加总月度流量，余额取年末值，非完整年度明确标注。年报接入真实开发商年末净资产排名，按所选年度的实际状态列示。

项目结算按本公司权益计算实际资金流与剩余净资产。商票、项目贷款和未付地价不能当作利润；结算时按余额预留未清偿义务，未来利息不预测。公司统借利息按存货账面额分摊，无归属费用留在公司报表。IRR按月资金流年化；多根、缺历史或仍有非现金资产时说明无法核实的原因。自有资金回正要求此后累计收支持续非负。

新档流水由种子与命令回放重建，不写GameState快照。旧v1–v5档按各版冻结内核和同日指令边界回溯开局至迁移日的流水、月报、决策和项目结算；核对全部经济末态及现金，保持原现金、债务、项目、市场和随机数。若统计回溯异常，原经济档仍可读取，报表明确覆盖范围和旧项目缺失。破产复盘保留规模、杠杆、决策和首次现金转负原因。完整口径与初阶段验收见[tests/acceptance/B5-REPORT.md](tests/acceptance/B5-REPORT.md)，162项测试和旧档回溯证据见[tests/acceptance/B5e-REPORT.md](tests/acceptance/B5e-REPORT.md)。

### B10 借款拿地与捂盘监管

现金付款先使用自有资金。调控/下行期实际使用借款支付土地，被抽查后按违规金额10%罚款、对应片区禁拍12个月。保证金落拍退回不罚；禁拍前未结拍报名会撤回退押。资金归因从v12迁移日开始，旧现金不追溯认定为违规来源。

未交付项目报价达市场115%，连续6个月月成交不足1%，会在抽查中被撤销预售证并罚剩余货值权益份额1%。撤证后先整改3个月，降到105%以内申请复审，审批通过才恢复预售；正常等待备案与工程停工不累计。界面显示期限及操作条件。规则与验收见 [B10验收](tests/acceptance/B10-REPORT.md)。

### B11 片区购房政策

### B13 模式与难度

首次开局和“重新开始”可选生涯、挑战或沙盒，再选择从容/标准/严峻。初始资金、周期幅度、监管预警提前量和AI激进程度随难度变化；界面显示该场景实际资金。确认后设置固定并写入指令日志。取消保留当前进度，确认重开会保留一份本机原档备份；建议另外导出存档。

- 生涯：标准档保持原有5亿元起步与30年结算，可继续经营。
- 千亿销售挑战：大型公司和供地规模开局，5年内新增权益销售达到1000亿元。资本投入、借款与收购承接的旧合同不计销售。
- 橙档下行挑战：真实橙档、3处在建项目、14亿元长期借款；本轮下行结束时须正常经营、现金非负且净资产为正。
- 保交楼挑战：接手已违约公司、2处停工4个月的项目、6亿元债务及原预售义务。原现金缺口1亿元，标准档5亿元救助资本到账后现金4亿元；36个月内由本公司全部交付并恢复正常经营，交付前转让或政府接管即失败。接手前项目流水不虚构，完整项目IRR标为无法核实。
- 沙盒：所有地图首日开放，可手动注资50亿元；月末现金不足时自动注资至1亿元防止公司破产。资金列资本投入、不算利润，原借款照常还本付息，项目仍可能停工或被接管。

挑战进度与结果在财务页显示，结束时记入回合待处理，结果保存后仍可继续经营。v15旧档迁移默认标准生涯，冻结v14历史和合同不改。验证与新参数见[B13验收](tests/acceptance/B13-REPORT.md)。

### B14 转让报价与交付后估算

负报价时项目卡解释预收房款在交付前仍为负债；项目融资导致的净补付另行说明。“交付后再转让”按当前已售面积不变、工程完成和土地款结清估算，交付时同时结转已售房屋成本，仅对剩余存货报价。当前债务本金只用于比较，实际销售、融资、还本和事故会改变结果；剩余工程款、土地款和监管款单列，报价差额不是新增利润。见[B14验收](tests/acceptance/B14-REPORT.md)。

## D3 批量风险统计

`npm run balance`默认两种策略各200局×30年，打印净资产、收益、破产触发支出分布和下行期最大回撤。可设`RUNS`、`YEARS`、`START_SEED`（正整数）；`SEASONS=1` 按真实开局开启季节/政策事件（默认关闭，与裸开局一致）；例如：

```bash
RUNS=200 YEARS=30 START_SEED=201 OUTPUT=tests/acceptance/my-balance.json npm run balance
```

归因取最终连续危机首月最后一次现金转负支出，表示直接触发项，不是完整经营成因。回撤按下行月末净资产对开局至该月的历史峰值统计，每局先求最大金额/比例，再汇总；未经历下行的局显示覆盖缺失，不填零。非正峰值不算比例，负净资产可出现超过100%的回撤；不覆盖月内波动。JSON保留配置摘要、各局种子、触发流水索引和峰值/端点日期，可复核。结果见[D3验收](tests/acceptance/D3-REPORT.md)。
