## 玩家可见变化

- 招聘、任命、撤岗、调岗和解雇的日志能够校验并重新读取，自动档、手动槽和文件导入使用同一套规则。
- 早期v16没有记录经济规则版本。读取时先展示历史日期、现金和净资产，玩家核对后创建续玩副本。原文件及旧自动档保持原样；不会凭“能回放”就推断正确版本。
- 当前提供原实时版（683b717，10月26日）和回合制员工版（2421210，10月29日）的冻结回放。若两个候选都不符，或存档曾在多个无标识的经济版本间续玩，应导出并保留原档，不能强选。没有足够来源信息时，不承诺自动重建所有中间版本的混合历史。
- “存档与读档”可导出旧主档、本地原件和替换前的历史备份。格式损坏、回放失败、恢复取消或备份写入失败都不自动重开或覆盖原件。
- 现金续航计入已签员工工资（包括待命），工程预测计入当前项目经理、首月已知季节事件；后续月按季节基准，不预测未来随机事件，岗位/能力/月薪按当前值保持。

## 文件与存储格式

新文件保留种子、日期、指令日志、revision和已有迁移边界，新增：

```json
{
  "version": 17,
  "rulesRevision": "turns-2421210",
  "legacyV16": {
    "profile": "original-683b717",
    "untilDay": 360,
    "logCount": 6
  }
}
```

`legacyV16`仅用于经核对的旧v16恢复。边界之前用冻结内核，之后按当前规则经营；同一天的指令用logCount区分，禁止把后续指令算入旧规则。新开局不需要这个字段。未知规则标识和非法边界拒绝读取，不猜测。

格式17写入localStorage的`fdc-save-v17`与IndexedDB `fdc-saves/saves`的`current-v17`。旧`fdc-save-v1`与`current`只读，不由升级写回覆盖。新格式已存在但损坏时，不静默倒退到旧格式进度。

导入原文和替换前进度都会留档；重开、手动槽覆盖前，在本地以不覆盖已有键的方式保留原文。IDB替换新主档前的备份和新写入在同一读写事务中完成；事务失败时旧主档保持不变。只有同一规则、同一边界、同一日志前缀的单向续玩可普通覆盖；换局、倒档、进度分支和替换失败后的重试仍先归档。主档与本地备份分支冲突时不猜选，存档页可明确读取副本。正常月末自动保存不无限归档每个revision，避免把存储写满。

v1—v15继续使用既有冻结链。其历史断点已经有版本信息，因此正常迁移不需要猜测v16来源。模拟内核版本未更改，不等于继续复用无标识存档格式：后续改变经济规则必须更新rulesRevision并冻结旧规则。
